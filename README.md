# Death-1C — Удаление старых задублированных сеансов на сервере 1С

[![Build Windows App](https://github.com/zigorminsk-debug/Death-1C-/actions/workflows/build.yml/badge.svg)](https://github.com/zigorminsk-debug/Death-1C-/actions/workflows/build.yml)

Нативное графическое приложение для **Windows** (написано на **Go + Fyne v2**) для администрирования сеансов сервера **1С:Предприятие 8.3**: просмотра всех запущенных сеансов и автоматического завершения старых задублированных сеансов с сохранением только максимально актуального сеанса по каждому пользователю.

---

## Основные возможности

- **Однократный ввод учётных данных администратора**:
  - Адрес сервера 1С, режим подключения и учётные данные администратора кластера вводятся **один раз** при первом запуске.
  - Программа автоматически запоминает настройки в `%AppData%\Death1C\config.json`, шифруя пароль средствами **Windows DPAPI (`CryptProtectData`)** с привязкой к текущей учётной записи Windows.
  - При последующих запусках панель настроек автоматически сворачивается в компактную строку состояния (при необходимости её можно развернуть кнопкой **«Изменить учётные данные»**).
- **Кнопка «Показать сеансы»**:
  - Подключается к серверу 1С, опрашивает кластеры и информационные базы, загружает **все запущенные сеансы** и наглядно помечает статус каждого сеанса (`Актуальный`, `СТАРЫЙ (дубль)`, `Конфигуратор`, `Системный`).
- **Кнопка «Удалить старые»**:
  - Получает актуальный срез сеансов с сервера, группирует пользовательские сеансы по каждому пользователю и завершает все старые дублирующиеся сеансы, **оставляя только максимально актуальный сеанс**.
  - Критерии выбора максимально актуального сеанса пользователя:
    1. Активный (не спящий, `hibernate = no`) сеанс всегда приоритетнее спящего (`hibernate = yes`).
    2. Наиболее свежее время последней активности (`last-active-at`).
    3. При равенстве активности — наиболее позднее время запуска (`started-at`) и наибольший номер сеанса (`session-id`).
  - Фоновые и системные задания (`BackgroundJob`, `SystemBackgroundJob`, `JobScheduler`, `SrvrConsole`, `RAS`), а также по умолчанию сеансы `Конфигуратора (Designer)` защищены от завершения.
- **Два способа подключения к серверу 1С**:
  1. **RAC / RAS (рекомендуется, порт `1545`)** — штатная утилита администрирования `rac.exe` (путь к `rac.exe` определяется на ПК автоматически в `C:\Program Files\1cv8\*\bin\rac.exe` и `C:\Program Files (x86)\1cv8\*\bin\rac.exe`, корректно декодируются кодировки `CP866`, `Windows-1251` и `UTF-8`).
  2. **COM (`V83.COMConnector`, порт `1540`)** — прямое подключение к агенту сервера 1С (`ragent`) без необходимости запуска службы `RAS` (с автоматической поддержкой как 64-битной, так и 32-битной регистрации `comcntr.dll`).

## Автоматическая сборка в GitHub Actions

Каждая сборка выполняется автоматически в **GitHub Actions** (`.github/workflows/build.yml`) на окружении `windows-latest`:

- Каждой сборке автоматически присваивается **порядковый номер** (`Build #1`, `Build #2`, `Build #3`, … через `github.run_number`).
- Порядковый номер сборки встраивается:
  - в заголовок окна и нижнюю панель программы (`Сборка #N (v1.0.N)`);
  - в окно **«О программе»**;
  - в ресурсы исполняемого файла Windows (`VERSIONINFO` в свойствах `.exe` + иконка приложения);
  - в артефакты сборки GitHub Actions и публикуемый GitHub Release (`Death-1C-build-N.exe`).

Готовый `.exe` можно скачать во вкладке **[Actions](https://github.com/zigorminsk-debug/Death-1C-/actions)** или **[Releases](https://github.com/zigorminsk-debug/Death-1C-/releases)**.

## Локальная сборка под Windows

Требования: Go 1.23+ и компилятор MinGW-w64 (`gcc`, для CGO/Fyne).

```powershell
$env:CGO_ENABLED = "1"
go mod tidy
go test ./internal/...
go build -trimpath -ldflags "-s -w -H=windowsgui" -o Death-1C.exe ./cmd/death1c
```
